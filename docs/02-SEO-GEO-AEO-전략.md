# 02. SEO / GEO / AEO 설계와 네이버 대응

이 문서는 **코드에 이미 반영된 것**과 **운영자가 직접 해야 하는 것**을 구분해서 적습니다.

## 1. 코드에 반영된 것

### 1-1. 페이지마다 다른 제목 · 설명

| 페이지 | `<title>` 패턴 |
|---|---|
| 행정구 | `강남구 마사지 \| 출장마사지·홈타이 로드샵 13곳 - 브랜드` |
| 행정동 | `역삼동 마사지 \| 서울 강남구 출장마사지·홈타이 안내 - 브랜드` |
| 업소 | `소율 길 테라피 \| 서울 강남구 역삼동 로드샵 - 브랜드` |

메타 설명은 `kkuk_meta_desc()` 가 지역 팩트(역·랜드마크·등록 수)를 섞어 **페이지마다 다른 문장**으로 만듭니다.

### 1-2. 구조화 데이터 (JSON-LD `@graph`)

| 타입 | 적용 페이지 | 역할 |

### 1-3. GEO (지역 질의 대응)

- `geo.region` — `KR-11`(서울) / `KR-41`(경기) / `KR-28`(인천)
- `geo.placename`, `geo.position`, `ICBM` 메타
- `areaServed` 에 **행정 구역명 + `GeoCircle`(반경 4km)** 동시 지정
- 업소 `address` 에 `addressRegion` / `addressLocality` / `streetAddress` 분리
- 본문이 역명·랜드마크·인접 구를 실제로 언급 → "강남역 근처 마사지" 같은 질의와 맞물림

### 1-4. AEO (답변 최적화)

- FAQ 답변은 **첫 문장이 곧 답**이 되도록 작성 (`가능합니다.` → 이유 → 전화번호)
- 첫 번째 질문은 `open` 상태로 렌더 → 크롤러와 사용자 모두 답을 즉시 봄
- `speakable` 로 `.k-lead`, `.k-faq__a`, `.k-answer` 지정
- 본문 `h2` 에 자동 앵커(`#sec-1`) 부여 → 딥링크 가능

### 1-5. 내부 링크 그래프

```
홈 ─ 시도 ─ 행정구 ─ 행정동 ─ 업소
       │        │        └ 형제 동 3곳
       │        ├ 인접 구 (시드의 '인접지역')
       │        └ 같은 시도 다른 구 24곳
       └ 구 카드마다 대표 동 3곳
```

업소 상세에서도 동 → 구 → 시도로 되돌아가는 링크를 둡니다.
고아 페이지가 생기지 않고, 지역 축으로 주제가 묶입니다.

### 1-6. 색인 산출물

- `/sitemap.xml` — 1,222개 URL, 깊이별 priority
- `/rss.xml` — 네이버 서치어드바이저 RSS 제출용
- `/robots.txt` — Yeti(네이버) · Daumoa 명시 허용, `/bbs/` `/adm/` `/plugin/` 차단

## 2. 네이버 대응에 대한 정확한 설명

**C-Rank 는 원래 네이버 블로그 검색의 출처 신뢰도 모델**입니다.
일반 웹사이트의 순위를 C-Rank 가 직접 매기는 것은 아닙니다.
다만 C-Rank 와 D.I.A. 가 평가하는 **"무엇을 좋은 문서로 보는가"** 는 사이트에도 그대로 적용됩니다.
이 프로젝트는 그 원리를 구조로 옮겼습니다.

| C-Rank / D.I.A. 가 보는 것 | 이 프로젝트의 대응 |
|---|---|
| 출처의 **주제 일관성** | 사이트 전체가 "지역 × 마사지" 한 주제. 잡다한 카테고리 없음 |
| 문서의 **독창성** | 308개 페이지 전부 1,500자 이상, 최대 유사도 0.296 (`check_dup.php` 로 상시 검증) |
| **맥락** (지역·실체 정보) | 역명·노선·랜드마크·인접 구 등 실제 지역 팩트를 본문에 사용 |
| **연결성** | 구↔동↔인접구 내부 링크, 고아 페이지 0 |
| **체류 시간 · 이탈** | 업종 필터, 검색, FAQ 아코디언, 동별 비교 동선 |
| **모바일 경험** | 반응형 + 고정 전화연결 바 + 탭타깃 48px 이상 |
| 출처 **신뢰 정보** | 사업자 정보 · 서비스 성격 고지 · 의료 행위 아님 명시 |

### 운영자가 직접 해야 하는 것

1. **네이버 서치어드바이저** 등록 → 소유확인 → `KKUK_NAVER_VERIFY` 입력
2. 사이트맵(`/sitemap.xml`) · RSS(`/rss.xml`) 제출
3. **구글 서치콘솔** 등록 → `KKUK_GSC_VERIFY` 입력
4. 네이버 **스마트플레이스** 등록 (지역 업체는 플레이스가 사실상 1순위 유입 경로)
5. 수집 요청은 한 번에 몰지 말고, 구 단위로 나눠 점진적으로

> 네이버는 신규 도메인의 색인 반영이 느립니다. 2~8주를 보수적으로 잡으세요.
> 이 기간에 페이지를 대량으로 갈아엎으면 평가가 초기화됩니다.

## 3. 중복 · 유사 · 스팸 패널티 회피

이전 플랫폼과의 중복이 가장 큰 위험 요소라고 하셨으므로, 네 겹으로 막았습니다.

1. **구조 분리** — 레이아웃·클래스 체계(`k-` 접두어)·URL 패턴을 새로 설계
2. **문장 생성 축이 4개** — 섹션 순서(12! 중 추출) × 문형(3~4종) × 동의어(15군 × 4) × 지역 팩트
   - 구 페이지와 동 페이지는 **섹션 풀 자체가 다릅니다** (어휘·어조 분리)
3. **자동 검증** — `php tools/check_dup.php` 가 모든 쌍의 자카드 유사도를 출력
   - 현재 최대 0.2959 / 평균 0.0456
   - 기준: 0.30 미만 안전 / 0.30~0.45 주의 / 0.45 이상 수정
4. **가상 데이터 색인 차단** — `KKUK_DEMO_DATA=true` 인 동안 전 페이지 `noindex`

### 이전 플랫폼과 대조할 때 확인할 것

- [ ] `<title>` · 메타 설명 패턴이 겹치지 않는가
- [ ] 본문 첫 문단이 같은 문형으로 시작하지 않는가
- [ ] 업소 디스크립션 문형이 재사용되지 않았는가
- [ ] 두 사이트가 같은 전화번호·사업자 정보를 쓰는 경우, **상호와 콘텐츠만큼은 반드시 분리**
- [ ] 이전 사이트에서 복사해 온 문장이 하나도 없는가

> 같은 운영자의 사이트가 여러 개일 때, 검색엔진은 "같은 출처가 비슷한 문서를 여러 개 냈다"로 봅니다.
> 디자인보다 **문장 중복**이 훨씬 치명적입니다.

## 4. 키워드 배치 원칙

| 위치 | 들어가는 키워드 |
|---|---|
| `<title>` | 지역명 + 마사지 + 출장마사지/홈타이 |
| H1 | `서울 강남구 마사지 · 출장마사지 · 홈타이` |
| 메타 설명 | 지역명 + 등록 수 + 역명 + 전화번호 |
| 본문 | 섹션 제목에 지역명, 출장·홈타이 섹션 별도 |
| **로드샵 · 스파 디스크립션** | **`출장 마사지` + `홈타이` 필수** (생성 시 검증, 누락 0건) |
| 전화 버튼 | `출장마사지` 고정 노출 |
| 이미지 | SVG `aria-label` 에 지역명 + 업종 |

키워드를 더 밀어 넣지 마세요. 현재 밀도가 상한에 가깝습니다.
