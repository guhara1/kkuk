# 06. 네이버 · 구글 색인 가속 가이드

사이트 주소 : **https://kkuk-ary.pages.dev**

---

## 0. 색인 정책이 바뀌었습니다 (중요)

예전에는 가상 업소 데이터 때문에 **전 페이지를 noindex** 로 막아 두었습니다.
지금은 색인을 열되, **가짜 정보만 골라 막는 방식**으로 바꿨습니다.

| 페이지 | 색인 | 이유 |
|---|---|---|
| 홈 · 시도 · 행정구 · 행정동 | **index, follow** | 실제 행정구역과 이용 안내를 담은 고유 콘텐츠 (1,500자 이상) |
| 업소 상세 | **noindex, follow** | 가상 데이터. 링크는 따라가되 검색 결과에는 노출하지 않음 |
| 검색 · 404 | noindex, follow | 색인 가치 없음 |

- `robots.txt` 는 **수집을 막지 않습니다.** robots.txt 로 막으면 크롤러가 `meta robots` 를 읽지 못해
  오히려 색인 제어가 안 됩니다. 수집은 열고 색인은 페이지별로 통제합니다.
- 사이트맵에도 **업소 페이지는 넣지 않습니다**. 실제 업체 정보로 교체하고
  `KKUK_DEMO_DATA=false` 로 두면 업소 페이지가 색인 대상이 되고 `sitemap-shop.xml` 이 생성됩니다.

## 1. 제공되는 색인 산출물

| 파일 | 내용 |
|---|---|
| `/sitemap.xml` | **사이트맵 인덱스** — 아래 파트를 묶는다 |
| `/sitemap-core.xml` | 홈 · 전체 지역 목록 · 시도 3곳 |
| `/sitemap-gu.xml` | 행정구 83곳 |
| `/sitemap-dong.xml` | 행정동 778곳 |
| `/sitemap-shop.xml` | 업소 (실데이터 전환 후에만 생성) |
| `/rss.xml` | 네이버 서치어드바이저 RSS 제출용 (시도 → 구 → 동 순) |
| `/robots.txt` | Yeti·Googlebot·Daumoa·bingbot 명시 허용 + 사이트맵 선언 |
| `/{32자리}.txt` | IndexNow 키 파일 (빌드 로그에 파일명 출력) |
| `/sitemap/` | **HTML 사이트맵** — 모든 지역 페이지를 사람이 볼 수 있게 모은 페이지 |

> 사이트맵을 쪼갠 이유 : 한 파일에 2,600개를 넣는 것보다 구역별로 나누면
> 검색엔진이 나눠 수집하고, 어느 구역이 색인되고 어느 구역이 빠졌는지 추적할 수 있습니다.

## 2. 네이버 — 서치어드바이저

> 네이버는 신규 사이트 반영이 느립니다. **2~8주**를 보수적으로 잡으세요.

1. <https://searchadvisor.naver.com> 접속 → **웹마스터 도구** → 사이트 등록
   - `https://kkuk-ary.pages.dev` 입력
2. **사이트 소유확인** → HTML 태그 방식 선택 → 받은 `content` 값을 설정에 넣고 재빌드
   ```php
   // g5/plugin/kkuk/_common.php
   define('KKUK_NAVER_VERIFY', '받은값');
   ```
   ```bash
   php tools/build_static.php && git add dist && git commit -m "네이버 소유확인" && git push
   ```
3. **요청 → 사이트맵 제출** : `sitemap.xml` 하나만 넣으면 인덱스를 따라 나머지를 읽습니다.
   잘 안 잡히면 `sitemap-core.xml`, `sitemap-gu.xml`, `sitemap-dong.xml` 을 각각 제출하세요.
4. **요청 → RSS 제출** : `rss.xml`
5. **요청 → 웹 페이지 수집** : 하루 한도만큼 직접 요청합니다.
   순서는 **홈 → 전체 지역 목록(`/sitemap/`) → 시도 3곳 → 등록 수 많은 구부터**
6. **검증 → robots.txt / 사이트맵** 에서 오류가 없는지 확인

### 네이버에서 더 중요한 것

- **네이버 스마트플레이스 등록** — 지역 업종은 플레이스가 사실상 1순위 유입 경로입니다.
  웹사이트 색인보다 이쪽이 먼저 효과가 납니다.
- 실제 업체 정보와 **동일한 상호·전화번호·주소**를 플레이스와 사이트에 쓰는 것이 신뢰도에 유리합니다.

## 3. 구글 — 서치 콘솔

1. <https://search.google.com/search-console> → 속성 추가 → **URL 접두어** → `https://kkuk-ary.pages.dev/`
2. 소유확인 : HTML 태그 방식 → 값 입력 후 재빌드
   ```php
   define('KKUK_GSC_VERIFY', '받은값');
   ```
3. **Sitemaps** 메뉴에 `sitemap.xml` 제출
4. **URL 검사** → 홈과 `/sitemap/` 를 "색인 생성 요청"
   (하루 요청 수에 제한이 있으니 상위 페이지부터)

> **주의** — 구글 Indexing API 는 채용공고(JobPosting)와 라이브 스트림 전용입니다.
> 일반 페이지에 쓰면 정책 위반이라 쓰지 않았습니다. 일반 페이지의 정식 경로는
> **사이트맵 + URL 검사**뿐입니다. "즉시 색인" 을 내세우는 외부 서비스는 대부분 효과가 없거나 위험합니다.

## 4. 그 외

- **빙 웹마스터** : 서치콘솔 계정으로 가져오기가 되어 10분이면 끝납니다. IndexNow 가 바로 동작합니다.
- **IndexNow** : 빌드 시 `/{키}.txt` 가 생성됩니다. 빙·얀덱스에 즉시 통보할 수 있습니다.
  **네이버와 구글은 IndexNow 를 지원하지 않습니다.**
  ```bash
  curl "https://api.indexnow.org/indexnow?url=https://kkuk-ary.pages.dev/&key=키값"
  ```
- **다음(카카오)** : 네이버 등록 후 자동 수집되는 편이며 별도 제출 창구는 축소되었습니다.

## 5. 구조로 색인을 당기는 장치

제출만큼 중요한 것이 **크롤러가 전 페이지에 몇 번 만에 닿는가** 입니다.

| 장치 | 효과 |
|---|---|
| `/sitemap/` HTML 사이트맵 (푸터 전역 링크) | 778개 행정동이 홈에서 **2단계** 안에 들어옴 |
| 구 → 소속 행정동 전체 링크 | 구 페이지 한 장이 평균 9개 동으로 연결 |
| 동 → 경계가 맞닿은 실제 인접 동 링크 | 동끼리 그물망으로 연결, 고아 페이지 0 |
| 롱테일 주제 앵커 | 같은 대상에 다양한 앵커 텍스트가 쌓여 주제 범위가 넓어짐 |
| 본문 목차 + 고정 섹션 앵커 | 체류 시간과 내부 탐색 증가 |

## 6. 색인 상태 점검

```bash
# 네이버
site:kkuk-ary.pages.dev
# 구글
site:kkuk-ary.pages.dev
```

수집은 됐는데 색인이 안 되면 대개 두 가지입니다.

1. **콘텐츠 품질** — 이 사이트는 전 페이지 1,500자 이상, 최대 유사도 0.30 미만으로 관리 중입니다.
   `php tools/check_dup.php` 로 언제든 재확인하세요.
2. **신뢰 신호 부족** — 사업자 정보, 실제 전화 응대, 외부 언급이 쌓여야 합니다.
   `pages.dev` 같은 무료 서브도메인은 자체 도메인보다 신뢰 축적이 느립니다.
   장기 운영이라면 **자체 도메인 구입을 권합니다**(연결 후 `KKUK_BASE` 변경 + 재빌드 필요).
